# 国内平价住宿接入重调研

> 后续进展：已取得用户授权并完成真实国内酒店和机票查价验证。最新实现、实测结果、覆盖失败项与支付边界见 [国内机票与住宿实测验收](domestic-travel-validation.md)。下文保留为取得凭据之前的选型记录，其中“尚无授权”等描述不代表当前状态。

核查日期：2026-11-09。

## 结论

按用户已确认的条件重新选型：**个人开发、没有公司；国内每间每晚 200–300 元；经济型连锁或民宿；保留站内完成预订的目标。**

现有 LiteAPI 巴黎沙盒只能证明测试交易流程能运行，没有证明国内平价库存适配，不作为本项目国内住宿主供应商。继续增加星级和价格筛选不能解决货源和交易权限问题。

建议把“国内货源验证”和“交易闭环验证”分开验收：

1. **第一个国内货源验证候选：途牛官方酒店 MCP。** 文档中的人民币预算、中文地点、房型与订单字段更适合个人原型验证；当前公开酒店支付流程需要返回途牛支付页，所以不能承诺全站内支付。
2. **美团个人酒旅 AI 接口作为并行候选。** 官方个人开发入口可见，但价格可能脱敏，公开资料不足以证明个人 Token 提供独立下单和支付接口；须拿授权后的实际工具定义和输出再决定。
3. **完整站内交易候选：同程／艺龙、美团酒店分销。** 这两条应进入商务及权限核实，不应现在宣称个人可直接接入上线。

目前**尚未找到并验证**同时满足“个人可直接获权、国内 200–300 元可售住宿、全站内正式下单及支付”的方案。这是未完成验证的边界，不等于市场上没有这类能力。

## 本次实际做过什么

- 复核现有代码：国内路线尚未接任何国内住宿供应商；LiteAPI 成功样本为海外沙盒。之前默认星级上限还排除了未标星酒店，不适合作为国内平价住宿的默认规则。
- 读取途牛官方公开文档，确认酒店搜索有价格区间、中文城市、酒店关键词和 POI 条件，详情包含人民币报价与下单参数。
- 无凭据访问官方 `https://openapi.tuniu.cn/hybrid/mcp/hotel`，HTTP **401**，确认不能匿名查询真实酒店。
- 读取对应 OAuth 资源发现地址，HTTP **200**，资源和授权服务器均指向途牛官方域名。
- 美团官方个人入口和官方 Skill 有公开检索内容；本机打开 Skill 页面遇到站点 WAF 拦截，没有绕过，没有取得 Token，也没有调用其酒店库存接口。
- 只进行公开资料、资源发现与访问边界核实，**没有得到国内 200–300 元实时房型，没有创建国内真实订单，没有扣款**。没有用公开文档示例价格冒充查询结果。

## 对个人开发者的实际限制

途牛当前文档额度为每分钟 5 次、每天 50 次，所有 API Key 共用；开放平台访问与手机号绑定的途牛会员关联。这适合谨慎验证个人原型，不适合让 AI 为长线行程的每一天反复全量搜索。应先合并连续住宿城市，缓存静态信息，并按用户选择逐项查详情。面向其他用户提供网站时，还需明确每个用户的账号授权归属以及对外展示、转售许可。[官方限制](https://open.tuniu.com/mcp/docs/guide/ratelimit.html)

“不跳转”也应分清：

- **站内预订、到店支付：** 如果获得供应商权限且存在非担保现付房型，可以不接本站在线收款。订单仍要有供应商确认，不能把提交请求当作预订成功。这是值得优先核实的国内路线。
- **站内预订、在线支付：** 需要供应商支持的完整创单、支付和订单状态接口，或明确允许嵌入的官方支付组件。返回支付 URL 不等于允许 iframe 嵌入，更不等于站内支付已接通。

这两种形式都尚未用本项目账号实测。不能因为开发了收银页就假定获得供应商结算和售后能力。

## 改为符合国内使用习惯的产品需求

- 默认预算上限 300 元／间／晚，不把 200 元以下的合适房源自动排除。
- 不设默认星级门槛，保留经济型、未标星、客栈和民宿；类型标签以供应商为准。
- 优先核对独立卫浴、床型、窗户、入住人数、停车、晚到接待与距离路线终点的绕行成本，不默认要求早餐或高星级。
- 对高原线路再增加供暖、热水等需要用户确认的条件，不从酒店名称臆测设施。
- 清楚展示标准间／大床房、每间和整单金额、担保或预付要求、取消时间、来源与查询时间。
- 同一家酒店只有在入住日期、人数、床型、餐食、退改相同的情况下才比较价格。平台会员优惠、促销券、API 结算价是否一致，要通过实际账号核实；不预设 API 一定更便宜。
- 不在无库存时悄悄升级预算、改城市或换成海外样例。

## 下一轮验证应如何做

先获得一项国内官方授权，再做小样本货源核验，不再先开发完整前端。

建议测试目的地：成都（城市对照）、丽江、香格里拉、芒康、丁青。覆盖常见旅游城市与当前长线行程中的县城落点。使用同一组未来工作日／周末日期，每间 2 位成人、1 间房，预算 200–300 元；也记录低于 200 元的合适房型，不用最低价宣传替代可售详情。

对每个目的地记录：

1. 搜索是否支持所需城市或县、200–300 元房源数量及分页情况。
2. 返回的具体酒店、房型、独卫／停车等证据及库存状态；缺字段注明待确认。
3. 详情价、下单前验价是否仍符合预算，以及退改、担保条件。
4. 是否能获取完整房价和正式订单 ID；个人账号有没有创建订单权限。
5. 支付是外链、可嵌入组件、独立支付 API，还是符合条件的到店现付；查单及取消如何处理。
6. 相同条件下与用户自己的平台账号页面对比；先解释价差，不直接标榜更便宜。

有货源但仅外链支付：仅通过“国内货源”验收，不通过原先的“全站内在线付款”验收。目标县城没有库存：将该目的地标记为不覆盖，不用巴黎沙盒成功替代。

## 下一步建议

以个人身份，先用途牛官方账号授权做 200–300 元真实货源验证；并核实美团个人酒旅入口实际返回能力。如果坚持完全站内交易，再评估同程／艺龙或美团分销的个人合作可行性、非担保到店付，以及正式在线支付权限。

现有海外沙盒保留为技术实验；不继续将其作为国内产品主线扩展。本轮只交付选型研究，不更改已运行的网站，也不自动注册账号、申请商务合作或下真实订单。
