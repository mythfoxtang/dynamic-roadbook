# 可交互旅行智能体：本轮核验与扩展方案

核验日期：2026-11-10（北京时间）。当前产品入口 `http://localhost:3010/agent/`。

## 这次结果说明了什么

读取了用户最近保存的行程和五项已选内容。宜昌酒店只读1/2页，北京酒店只读1/2页；上海→宜昌返回3个航班、北京→上海返回10个，供应商均声明1页。不能把单个查询的结果当成全市场可售库存。恩施→北京本次为空，不证明当天没有可行航线。

还发现一次模型把三峡之巅的住宿城市识别为宜昌，供应商仍返回了一个酒店。地点关键词不等于地理校验通过。[奉节县政府的景区介绍](https://www.cqfj.gov.cn/index/fjwl/jpjq/202209/t20220914_11109757.html)确认该景区属于奉节。本轮加入这条有出处的地点核对，拦住旧快照中的错位酒店；没有将错误城市酒店包装成附近住宿。当前只内置了这条已核实地点证据，还不是通用地理编码服务。

高铁不是接口接入失败：本轮真实复测上海→宜昌、2026-11-16、1成人，途牛返回16个车次、1页。此前智能体只允许机票/酒店/租车/门票任务，没有接入后台已有的火车工具，形成了界面能力缺口。现在模型可以按用户明确要求增加高铁备选、读取席别；既有航班仍保留，直到用户选择具体替代项。

租车目前仍没有真实授权货源。已有取还车规划与合作网关适配契约，不能算作已经接通真实车型、租金和异地还车费。高铁仅支持成人、含当天15天预售期；真实创单/支付未执行。

## 本轮实现

- 用自然语言继续沟通：要求更多、调整预算、停车/取消条件、时刻，或增加交通备选；DeepSeek产生受限工具动作，程序执行后显示实际结果。
- 一轮最多4个动作；只允许重查、继续翻页、筛选、新增备选，不允许模型下单、付款或取消订单。
- 翻页按钮显示已加载数量、筛选后数量、已读/总页数；可继续读取供应商分页。未知总页数时不声称已查全。
- 筛选在已加载结果中执行，未知设施不视为满足条件；补查后再让DeepSeek比较实际候选。更多数据不等于更多合格结果。
- 对话、筛选和已选内容恢复；调整一项不会清空其他选择。查询城市/日期/人数改变时，只失效相关任务选择。确认具体交通备选后，才替换同组原选择。
- 错位地点隔离与查价限流恢复。原服务继续在后台运行，构建使用独立目录后再切换。

途牛官方限制为同一账号所有Key共用每分钟5次、每天50次，暂不支持用户级定制。[官方限额](https://open.tuniu.com/mcp/docs/guide/ratelimit.html)。增加Key不能扩大同账号配额。本站计数只是本进程估算，不能当作官方剩余额度；其他进程和客户端也会消耗同一账号预算。

连接器目录也查过：本轮找到的旅行类连接器偏已有行程管理，未发现能直接补足本任务国内租车库存的已连接工具，因此没有为凑来源安装无关连接器。

## 建议采用的灵活方案

先把“对话决策”和“供应商”分开：DeepSeek负责理解意图、提出查询和比较；工具负责实际获取数据、分页、核实地点、报价口径与来源。用户选择保存为独立状态，不与某次模型输出绑定。

短期使用已接通API完成真实候选与交通备选，租车单列货源缺口。下一步对租车选择神州H5/API合作或专用官方网页只读辅助适配器：后者需要实际验证登录态、搜索条件、费用字段与稳定性，遇到必要登录/验证才让用户参与，不能声称本轮已经采集到租车报价。

正式使用时，再增加一个有授权的酒店/机票来源。推荐新增供应商适配器统一实现 `capabilities/search/next/detail`，返回来源、原始产品标识、查询条件、抓取时刻、价格口径和过期时间。对同一住宿/交通任务保留独立的来源会话与报价，不能把A供应商产品ID传给B创单；不同房型、日期或价格口径不做伪比价。

这是后续多源适配的目标架构，当前没有取得的供应商权限、网页采价与交易能力都不会显示为已上线。当前交付是对话工具循环、分页/筛选、高铁备选及明确的接入状态，真实租车和新增库存源仍待接入验证。

## 验证

`node --test lib/*.test.mjs scripts/*.test.mjs`；`node scripts/agent-dialogue.smoke.mjs http://localhost:3016` 为明确fixture的多轮交互验证；`node scripts/agent-ui.smoke.mjs http://localhost:3016` 保留原选择流程回归。`npm.cmd run service:build` 生成独立生产构建。

真实只读高铁结果保存在Git忽略的 `.automation/flexible-train-check.json`。真实DeepSeek多轮联调使用独立临时浏览器会话，避免测试消息覆盖用户的五项已选；证据保存到 `.automation/flexible-live-results.json`。未创建、支付或取消任何真实订单。

本轮真实两轮对话已通过：模型新增上海→宜昌高铁备选并取得16个车次，随后按追问继续读取宜昌酒店第二页，共9家；每轮均保留五项已选。96项Node测试、fixture多轮浏览器测试、原选择流程回归及生产构建通过。只将匹配原查询的真实补查结果和高铁备选发布到用户工作台，测试消息不带入真实对话。
