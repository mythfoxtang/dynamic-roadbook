## 怎么让“全覆盖”可以核验

分别定义覆盖，不使用单一模糊的“全”字：

1. 名录覆盖：每省最新官方 A 级清单逐项匹配，列出基准日期、基准数、成功匹配、重复、更名、撤销和缺失项。只有在一个明确版本内逐项对账才能报告覆盖率。
2. 普通游玩点覆盖：公园、博物馆、街区、观景点等另建分类，多来源召回，保留来源和漏项反馈；没有完整基准时不显示伪覆盖百分比。
3. 景区内部覆盖：建立景区—分区—内部景点—入口/停车场层级，从官方导览及路线抽取必看点、可选点、接驳和顺序。多条记录不能仅凭同名或相近坐标直接合并。
4. 可执行覆盖：检查每个实际安排点的坐标、入口、时间预算、预约和最新运营状态；无法核实的字段标未知。非公开步道、索道、景交顺序不由地图驾车接口推断。

优先全国 A 级名录对账，再扩展普通地点。每个目的地输出“已安排/未安排及理由/待核实”，减少无声漏点。

## 高德具体接入路径

现有网站已有高德 JS PlaceSearch。推荐保留地图展示，新增服务端 Web 服务适配器，由现有智能体通过受限工具调用，统一 POI 关键词/周边/详情检索与交通路线查询；严格限制区域、记录分页截断，区分无结果、限流、配额和权限错误。餐饮围绕实际用餐时段的位置搜索，而非仅用当天最后一站。

官方也提供 MCP：https://developer.amap.com/api/mcp-server/summary ，涵盖搜索、地点详情、路径规划等；MCP 是接入协议，不增加景区数据库覆盖率。对现有 Next.js 网站优先直接 Web API，减少协议适配层；若需向外部 AI 客户端提供同样能力再评估 MCP。

本地上轮仅确认存在 JS Key，未确认 Web 服务 Key。正式真实请求必须使用对应类型凭据，不能假定 JS Key 通用；现阶段可继续研究与编写适配器，不声称已经接通。限额、费用、缓存和数据库再利用以当前账号与官方授权为准，不照抄第三方仓库配额数字。
